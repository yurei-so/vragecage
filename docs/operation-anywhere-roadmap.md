# Operation Anywhere roadmap

Last updated: 2026-10-22

## Objective

Build and validate reusable vehicle navigation across supported environmental zones. Keep world modeling, route planning, vehicle-specific local control, transition handling, recovery, and observability distinct. A zone transition is supported only when the vehicle and route can physically traverse it; otherwise the planner must report `NOT_SUPPORTED`.

## LocalVehicleTest readiness gates

- **Fresh `-p` baseline:** q's run `9b313fdf84e05de7818b1b047bf98afd` failed the passive baseline and exposed an unsupported start. C is retired from movement. V4R1 Blue is imported into the exact private worker root with matching world, plugin, and five-mod receipts; no `-p` runtime baseline exists. Use that private root for the fresh no-command baseline, then verify the genuine run receipt. The save does not attest load-time package bytes. Require an exact fresh grounded fixture before baseline. The passive JSONL provides run/session/grid identity, stream sequence, UTC, gameplay tick/time, chassis position/orientation and linear velocity, plus selected-grid wheel override/brake bits when controller resolution succeeds. It does not provide angular velocity, gravity, contact/normal, rotor-grid motion, or writer inventory. LocalVehicleTest adds angular velocity, gravity, per-wheel contact/normal and rotor-grid motion/readbacks, but its local callback counter is not a gameplay tick and its records lack a shared sample key. Accept distinct gameplay ticks and timestamps from raw passive JSONL; keep LocalVehicleTest evidence separately attributed and do not join records sample-for-sample until both streams share run/session/tick/sequence identity. Preserve first-valid samples, gaps and dropped-record counts explicitly.
- **Exact package and run receipts:** bind the fresh fixture ID, run ID, vehicle/controller/camera/grid IDs, source/import hash, package hashes, config hash, and authorization scope before launch. Recompute and verify every staged receipt against that exact instance; do not reuse q, B, or C receipts as proof for the fresh run.
- **Directional and chassis clearance:** verify measured gravity alignment, all four wheel support patches, and chassis clearance against terrain/voxel geometry. First establish which authoritative contact, suspension compression/travel, normal, or load fields the installed game API exposes. Require stable support across distinct ticks only when authoritative contact evidence exists; otherwise report support as unknown and label rays as proximity. The live camera test checks direction alignment (camera/controller forward dot at least 0.98) and casts a 4 m centerline ray beginning 1.5 m ahead; it does not assess wheel/lateral/overhead extent, chassis/terrain clearance, or swept volume. Bind a conservative full-assembly envelope receipt to run/tick/origin and nearest-hit details, and recheck at the movement boundary. Do not claim a swept-volume guarantee without bounded obstacle dimensions or conservative expansion. The current plugin readiness construction omits `FullAssemblyClearanceVerified`, whose default is false; `CanDispatch` rejects every Propulsion/Drive command while it is false, and this LocalVehicleTest path has no producer that can currently set it true. A run-bound full-envelope evidence producer and readiness binding are required before motion.

## Operating rules

- Each experiment records fixture/run identity, vehicle, start/destination, controller version, bounds, command sequence, observations, terminal status, evidence, and next action.
- Use `PASS`, `FAIL`, `INCONCLUSIVE`, `NOT_SUPPORTED`, or `NOT_TESTED`; command acceptance alone is not a movement pass.
- Use separate disposable clones for concurrent work. VESPER's discontinuity analysis is read-only; CODEX owns the separate motion-test clone.
- The local-test systemd deadline starts when its exact transient service starts; it is independent of game/mod ticks and escalates after a 10 s graceful-stop window to process-group termination. It does not explain or repair the A/B startup displacement.
- Startup pose evidence must distinguish the saved +1000 m placement edit from runtime movement. Capture the chassis and four wheel-grid transforms at entity initialization and first physics-ready tick; do not treat the delayed first sample as the load pose.
- Preserve original worlds, manual/production servers, shared cache, emergency-stop behavior, and uncommitted work. No commits, pushes, or deployments are authorized by this roadmap.
- Any newly required authority or protected-environment change remains outside the current scope and must be escalated.
